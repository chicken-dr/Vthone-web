Architecture Overview

Internal pipeline, component design, and data flow of the Vthon transpiler.

Pipeline Overview

The Vthon toolchain follows a classic compiler pipeline adapted for transpilation to Python:

Pipeline
.vth source
    │
    ▼
┌─────────────────────────────────────┐
│           LEXER                     │
│  indentation-aware tokens           │
│  (INDENT, DEDENT, LINE, EOF)        │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│           PARSER                    │
│  recursive-descent, Vthon AST       │
│  expressions as source fragments    │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│        TRANSPILER                   │
│  Vthon AST → Python source          │
│  validates with ast.parse()         │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│          RUNTIME                    │
│  compile() → CPython exec()         │
│  source-located error mapping       │
└─────────────────────────────────────┘

Key Characteristics

  • Single-pass lexer - Produces logical tokens with indentation tracking
  • Recursive-descent parser - Direct mapping from grammar rules to parser methods
  • Expression fragments - Expressions kept as strings, validated by Python's AST
  • Python AST validation - Generated code validated before execution
  • No VM - Direct CPython execution, zero runtime overhead

Lexer (lexer.py)

Responsibilities

  • Validate indentation (4-space multiples, no tabs)
  • Strip comments safely (respecting string literals)
  • Produce logical tokens: INDENT, DEDENT, LINE, EOF
  • Track source locations (line, column) for error reporting

Algorithm

  1. Pre-scan lines for indentation validation (tabs, 4-space multiples)
  2. Use Python's tokenize.generate_tokens to find logical line boundaries and strip comments
  3. Track indentation levels using a stack
  4. Emit INDENT/DEDENT tokens based on indentation changes
  5. Emit LINE tokens containing stripped source lines

Token Types

KindValueDescription
LINESource line (minus indent, comments)Statement or expression
INDENTEmptyIndentation increase
DEDENTEmptyIndentation decrease
EOFEmptyEnd of input

Parser (parser.py)

Approach

Recursive-descent parser with one method per grammar rule. Each statement type is matched using regex patterns against the LINE token value.

Key Methods

  • parse() - Entry point, returns Program
  • _suite() - Parse indented block
  • _statement() - Dispatch to statement parsers
  • _required_block() - Expect and consume INDENT...DEDENT
  • _split_assignment() - Parse assignment operators at depth 0

Expression Handling

Expressions are not parsed structurally. They are kept as source strings and passed through to the transpiler, which validates them using Python's ast.parse(mode='eval').

Assignment Parsing

Uses Python's tokenize to find assignment operators at nesting depth 0, avoiding false positives in function calls like print(x, y=1).

AST Nodes (ast_nodes.py)

Vthon-owned, source-located dataclasses. All nodes inherit from Node with line and column.

Node Hierarchy

Node (base)
├── Program
├── Statement (base)
│   ├── VariableDecl (let/const)
│   ├── Assignment
│   ├── ExpressionStmt
│   ├── ReturnStmt
│   ├── RaiseStmt
│   ├── KeywordStmt (break/continue/pass)
│   ├── ImportStmt
│   ├── FunctionDef
│   ├── ClassDef
│   ├── IfStmt (with IfBranch)
│   ├── WhileStmt
│   ├── ForStmt
│   └── TryStmt (with CatchClause)
├── IfBranch
└── CatchClause

Design Decisions

  • Dataclasses for simplicity and immouability
  • Source location on every node for diagnostics
  • Expressions stored as strings (not AST)
  • Flat hierarchy - no visitor pattern needed

Transpiler (transpiler.py)

Responsibilities

  • Lower Vthon AST nodes to Python source code
  • Manage indentation and scoping
  • Track const bindings for compile-time reassignment checks
  • Handle implicit self in class methods
  • Convert Vthon literals (true/false/null)
  • Validate generated Python with ast.parse()

Key Transformations

Constant Tracking

Uses a scope stack (self.constants) to track const names. On assignment, checks if target root name exists in any active scope.

Validation

After generation, runs ast.parse(generated_code) to ensure syntactic validity. Errors are mapped back to Vthon source locations.

Runtime (runtime.py)

Public API

# Parse source to Vthon AST
parse(source: str, filename: str = "") -> Program

# Transpile source to Python code
transpile(source: str, filename: str = "") -> str

# Execute source, return namespace
execute(source: str, filename: str = "", namespace: dict | None = None) -> dict

# Execute .vth file
run_file(path: str | Path, namespace: dict | None = None) -> dict

Execution Flow

  1. Parse source → Vthon AST
  2. Transpile AST → Python source
  3. Validate Python AST
  4. Compile with compile(code, filename, 'exec')
  5. Execute with exec(compiled, scope, scope)
  6. Return execution namespace

Namespace Setup

Default namespace includes __name__ = '__main__' and __file__ = filename.

CLI & REPL

CLI (cli.py)

  • vthon file.vth - Execute file
  • vthon run file.vth - Explicit run
  • vthon repl - Start REPL
  • vthon --emit-python file.vth - Print generated Python
  • vthon --version - Show version

REPL (repl.py)

  • Blank line executes accumulated block
  • Single non-colon line executes immediately
  • Persistent namespace across inputs
  • Ctrl-D / Ctrl-C to exit

Error Handling (errors.py)

Exception Hierarchy

VthonError (base)
├── VthonSyntaxError    # Lexing/parsing errors
├── VthonCompileError   # Transpilation errors (const reassignment, invalid Python)
└── VthonRuntimeError   # Execution errors (Python exceptions)

Source Location

All errors carry SourceLocation with filename, line, column, and the offending source_line for formatted output:

hello.vth:3:5: error: cannot assign to constant 'PI'
  const PI = 3.14
  PI = 3.14
    ^

Design Principles

  1. No CPython fork - Python interoperability is a language feature, not an implementation shortcut hidden from the AST pipeline.
  2. Source-located diagnostics - Every error maps to original Vthon source.
  3. Expressions remain Python-compatible - Vthon owns declaration/control flow syntax; expressions use Python syntax.
  4. Vthon AST is the authority - Generated Python is validated before execution.
  5. Stdlib only - Zero dependencies, runs anywhere Python 3.10+ runs.
  6. Minimal surface area - ~870 lines, each component independently testable.
