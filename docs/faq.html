FAQ

Common questions about Vthon, answered.

General Questions

What is Vthon?

Vthon is a small, readable, indentation-based programming language that transpiles to Python and runs on CPython. It has its own lexer, parser, AST, transpiler, CLI, and REPL—built from scratch without forking CPython.

Why not just use Python?

Vthon provides a cleaner syntax (no colons on simple statements, implicit self in methods, let/const declarations) while maintaining full Python ecosystem compatibility. You get the best of both worlds: Vthon's syntax for your code, Python's libraries for everything else.

Is Vthon a Python implementation?

No. Vthon transpiles to Python source code, which is then executed by the standard CPython interpreter. There's no custom VM or interpreter—your code runs on the same CPython you already use.

What's the current version and status?

Vthon is at MVP 0.1.0 (released August 2026). It's a minimal viable product with core language features working. See the Roadmap for planned features.

Technical Questions

How does Python interoperability work?

Use py import module or py from module import name to import Python packages. These statements pass through to the generated Python unchanged. Imported objects are available directly in Vthon scope—no wrapping, no conversion needed. Vthon values use Python runtime representations.

Are const values truly immutable?

No. Constants are a compile-time protection only. The transpiler rejects direct reassignment to a const name within the same compilation unit. However, mutation through aliases, container modification, or Python reflection is possible. It's a linting aid, not a security boundary.

How are expressions handled?

Expressions are kept as source strings during parsing and validated by the transpiler using Python's ast.parse(mode='eval'). Vthon literals true, false, null are converted to True, False, None during transpilation. All Python operators work.

What Python version is required?

Python 3.10+ is required. Vthon uses modern Python features like pattern matching (match/case) in the transpiler, and the generated code may use 3.10+ syntax.

Does Vthon have a standard library?

Not yet. The MVP relies entirely on Python's standard library via py import. A Vthon-native standard library is planned for v1.0+ (see Roadmap).

Usage Questions

How do I run a Vthon file? 
vthon program.vth
# or
vthon run program.vth
How do I see the generated Python? 
vthon --emit-python program.vth
Can I use Vthon as a library?

Yes. Import vthon.runtime and use parse(), transpile(), execute(), or run_file(). See the API Reference for details.

Is there editor support?

Not yet. A Language Server (LSP) and VS Code extension are planned for v1.0+. For now, you can use Python syntax highlighting for .vth files since the syntax is similar.

How do I report a bug?

Open an issue on GitHub Issues with a minimal reproduction case, your Vthon version (vthon --version), Python version, and OS.
